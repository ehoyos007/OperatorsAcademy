01 Terminal Basics

The Terminal is a text-based way to talk to your computer. Instead of clicking through folders, you type commands. It's faster and more powerful — and it's where Claude Code lives.

Opening Terminal

Press Cmd + Space, type Terminal, hit Enter. You'll see a window with a blinking cursor. That's it — you're in.

Where am I?

When you open Terminal, you start in your home folder (like /Users/dylanhodge). Think of it as your desktop — everything branches out from here.

Terminal — Essential Commands 
$ pwd                       # Where am I? (print working directory)
/Users/dylanhodge

$ ls                        # What's in this folder?
Desktop   Documents   Downloads   Projects

$ cd Projects               # Move into the Projects folder

$ cd ..                     # Go back up one folder

$ mkdir my-app              # Create a new folder called "my-app"

$ cd my-app                 # Move into it

$ clear                     # Clean up the screen
Tip Press the Tab key to auto-complete folder and file names. Type cd Pro then Tab — it'll fill in Projects for you.

The 5 commands you'll use daily

📍

pwd

"Where am I?" Shows your current folder path.

📂

🚶

"Go there." Moves you into a folder. cd .. goes back.

"Clean up." Clears your Terminal screen.

02 Claude Code

Claude Code is an AI coding assistant that lives in your Terminal. You talk to it in plain English and it writes code, runs commands, creates files, and deploys your projects.

First launch

Terminal 
$ claude                    # Launch Claude Code

The first time you run this, it'll ask you to sign in with your Anthropic account. Follow the link it gives you, authorize in your browser, and you're connected.

How it works

Once Claude Code is running, you just type what you want in plain English. It reads your files, writes code, runs tests, and deploys — all from the same window.

Claude Code Session 
you: create a landing page for a coffee subscription service

Claude will analyze your project, create files, write HTML/CSS/JS,
and tell you what it built. You review, give feedback, and iterate.

you: make the hero section taller and add a "Start Free Trial" button

Claude edits the existing files. No copy-pasting. No switching tools.
Key concept Claude Code works inside whatever folder you launched it from. If you're in ~/Projects/my-app, it can see and edit files in that project. Always cd into your project folder first.

Useful commands inside Claude Code

See all available commands and shortcuts.

Summarize the conversation so far (saves memory for long sessions).

03 Your First Project

Let's create a project from scratch and set it up with the full documentation system.

  1. Create a project folder — Open Terminal and run: mkdir -p ~/Projects/my-first-app && cd ~/Projects/my-first-app
  2. Initialize git — This tracks your changes (like version history): git init
  3. Launch Claude Code — Start your AI assistant: claude
  4. Say "initialize project" — Claude will create all 8 documentation files that keep your project organized. It analyzes your folder and scaffolds everything automatically.
  5. Tell Claude what to build — Describe your project in plain English. Be specific: "Build a personal portfolio site with a hero section, about me, and a contact form."
  6. Test it — Say "run QA" and Claude runs all checks.
  7. Ship it — Say "ship" and Claude commits your code, creates a branch, and opens a PR.
Pro move At the end of every work session, say "wrap up". Claude saves your progress so next time you can say "let's continue" and pick up exactly where you left off.

04 The 8-File System

Every project uses 8 markdown files to stay organized. Claude reads them at the start of every session and updates them as you work. Say "initialize project" to create them all at once.

📖

CONTEXT.md

Background knowledge about your project — tech stack, domain terms, how things connect.

✅

TASKS.md

Your task board. What's done, what's in progress, what's next.

🧪

TEST_LOG.md

QA results. Every test run is logged here so you can track what works.

📐

PLAN.md

Strategic blueprint for complex features. Think before building.

📒

PROGRESS.md

Session-by-session log of what you did. Like a flight log.

🧠

BRAIN.md

Decisions and insights that carry across sessions. Your project's memory.

🎯

VISION.md

The "why" — what success looks like, hard constraints, tradeoff rules.

⚙️

CLAUDE.md

Per-project instructions for Claude. Tech stack, commands, conventions.

Why this matters These files give Claude persistent memory across sessions. Without them, every time you start a new session Claude forgets everything. With them, it picks up right where you left off.

05 The Shipping Workflow

This is the core loop. Build something, test it, ship it, deploy it. Four phrases to remember.

Build Your Feature
Tell Claude what to build in plain English
"run QA"
Lint + types + tests + build check
"ship"
Creates branch, commits, pushes, opens PR
"deploy"
Merges PR to main, deploys to production

What each step does

"run QA" — Claude runs your project's test suite: linting, type checking, unit tests, end-to-end tests, and a build check. Results get logged to TEST_LOG.md. If something fails, Claude tells you and helps fix it.

"ship" — Claude creates a feature branch (never pushes directly to main), stages your changes, writes a commit message, pushes to GitHub, and opens a Pull Request. You get a PR link back.

"deploy" — Claude merges your PR into main (squash merge, clean history), deletes the feature branch, and your hosting platform (Vercel, Netlify, etc.) auto-deploys. You get a production URL.

Important rule Never push directly to main. Always use feature branches. The "ship" command handles this automatically — if you're on main, it creates a branch first.

Session lifecycle

Typical Session 
# Starting a session
you: let's continue         # or: /pickup
Claude reads your docs, shows where you left off, suggests next action.

# Working
you: add a contact form to the homepage
you: make the submit button green
you: run QA

# Saving progress (no git)
you: wrap up               # Saves progress, writes handoff for next session

# Shipping (git)
you: ship                  # Branch + commit + push + PR

# Deploying (production)
you: deploy                # Merge PR + go live

07 Tips for New Builders

Common patterns that'll save you time.

Be specific with Claude

Instead of "make it look better", say "make the hero section 100vh, center the heading, and add a gradient background from dark blue to black." The more specific you are, the better the result on the first try.

Always work in your project folder

Before launching claude, make sure you're in the right folder:

Terminal 
$ cd ~/Projects/my-app
$ claude

When something breaks

  1. Don't panic. Say "debug this" or paste the error message. Claude can read error logs and trace the issue.
  2. If Claude is stuck, say /compact to free up memory, then re-explain what you need.
  3. If everything is broken, say /clear to start a fresh session. Your files are still on disk — nothing is lost.

The daily rhythm

Start

cd ~/Projects/my-app
claude
"let's continue"

Build

Describe features in plain English. Iterate with feedback. Say "step done" between tasks.

Test

"run QA" before shipping. Fix anything that fails.

Ship

"wrap up" to save. "ship" to push. "deploy" to go live.

Don't forget to wrap up If you close Terminal without saying "wrap up", Claude loses track of where you were. Always save your session before quitting.

Git basics (you'll pick this up naturally)

Git tracks every change you make. The toolkit handles git for you — you'll rarely need to run git commands directly. But here's what's happening behind the scenes:

  • Branch — A separate copy of your code for a feature. Keeps main clean.
  • Commit — A saved snapshot of your changes with a message.
  • Push — Send your commits to GitHub (the cloud).
  • PR (Pull Request) — A proposal to merge your branch into main.
  • Merge — Combine your branch's changes into main.
